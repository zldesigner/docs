# 训练计划 Skill

## 能力定义

训练计划 Skill 负责为用户提供**科学、个性化、动态调整的运动训练方案**。它不只是生成一份计划，而是全程陪伴计划的执行过程——记录完成情况、感知执行障碍、及时优化方案。

## 核心能力矩阵

| 能力 | 描述 | 数据依赖 |
|------|------|---------|
| **初始计划生成** | 基于用户目标和体能评估生成完整训练计划 | 用户画像、健康档案 |
| **动态计划调整** | 根据执行反馈、身体状态实时优化 | 执行记录、健康数据 |
| **单次训练设计** | 为特定场景设计单次训练内容 | 当前状态、可用设备 |
| **替代方案生成** | 当计划无法执行时，快速生成等效替代 | 当前约束条件 |
| **进度评估** | 定期评估训练效果并调整难度 | 历史执行数据、体测数据 |

## 交互范式

### 场景一：首次制定计划

<Tabs>
  <Tab title="对话示例">
    ```
    用户：我想开始健身，但不知道从哪里开始

    Agent：听起来你已经准备好迈出第一步了！让我先了解一下你的情况，
           这样我才能给你一个真正适合你的方案。

           你现在大概多久运动一次？
           A. 几乎不运动
           B. 偶尔运动（每月1-2次）
           C. 每周有时运动（1-2次）
           D. 已经有一定运动习惯

    用户：A，几乎不运动

    Agent：完全没问题！很多人都是这样开始的。对你来说，
           最重要的是建立习惯，而不是一开始就追求强度。

           你有什么特别想达到的效果吗？
           比如减脂、增肌、提升体能，或者只是想更健康一点？

    用户：主要想减肥，顺便想身材好看一点

    Agent：明白了！减脂 + 体型改善，这是个很棒的目标组合。

           我已经根据你的情况初步设计了一个4周入门计划，
           先看看整体方向对不对：

           📅 第1-2周：每周3次，每次30分钟
           重点：建立运动习惯 + 激活身体

           📅 第3-4周：每周3-4次，每次40分钟
           重点：逐渐增加强度 + 感受变化

           你一般哪几天比较方便运动？
    ```
  </Tab>
  <Tab title="UX 要点">
    **信息收集原则：**
    - 每次只问一个问题，避免让用户填写长表单
    - 用选项降低回答负担，但保留"其他"出口
    - 在收集信息的过程中同步给予肯定和解释

    **计划呈现原则：**
    - 先呈现整体框架，再展开具体内容
    - 用进度感强的视觉语言（周数、阶段感）
    - 明确"接下来需要用户做什么"

    **关键设计决策：**
    - 首次计划不追求完美，追求"够用 + 能坚持"
    - 第一周故意设置略低于用户能力的强度，确保成功体验
  </Tab>
</Tabs>

### 场景二：计划动态调整

```
[用户今日打卡后反馈]

Agent：今天的训练完成了！感觉怎么样？

用户：还好，就是腿有点酸，明天是腿部训练日，
      感觉有点担心

Agent：理解你的顾虑！延迟性肌肉酸痛（DOMS）在初期很正常，
       说明肌肉在适应训练。

       我帮你调整了明天的安排：

       原计划：腿部力量训练（深蹲、硬拉）
       ↓ 调整为
       调整后：上肢 + 核心训练，给腿部多一天恢复

       这样不影响整体训练量，但让你的腿部充分恢复。
       后天再做腿部训练，那时酸痛感应该消退了。

       你觉得这个调整可以吗？
```

### 场景三：无法完成训练时

```
用户：今天出差了，没有带运动装备，计划上是力量训练日

Agent：出差在外，条件有限很正常！我给你设计了一个
       不需要任何器械的酒店房间训练方案。

       🏨 出差版训练（25分钟）
       - 热身：原地高抬腿 × 3分钟
       - 俯卧撑 3组 × 最大次数
       - 深蹲 3组 × 15次
       - 平板支撑 3组 × 45秒
       - 弓步走 2组 × 12步

       效果≈原计划的75%，但维持了你的运动连续性。
       要我详细说明每个动作的要点吗？
```

## 计划生成逻辑

### 输入参数

```typescript
interface TrainingPlanInput {
  // 目标
  primaryGoal: 'fat_loss' | 'muscle_gain' | 'endurance' | 'flexibility' | 'general_fitness';
  timelineWeeks: number;

  // 体能基础
  currentLevel: 'beginner' | 'intermediate' | 'advanced';
  recentInjuries: Injury[];

  // 时间约束
  availableDaysPerWeek: number;
  sessionDurationMinutes: number;
  preferredTime: 'morning' | 'afternoon' | 'evening';

  // 设备条件
  equipment: Equipment[];
  location: 'gym' | 'home' | 'outdoor' | 'flexible';

  // 偏好
  preferredActivities: ActivityType[];
  dislikedActivities: ActivityType[];
}
```

### 计划结构

```typescript
interface TrainingPlan {
  id: string;
  name: string;
  durationWeeks: number;
  phases: TrainingPhase[];

  weeklySchedule: {
    [dayOfWeek: string]: WorkoutSession | 'rest' | 'active_recovery';
  };
}

interface WorkoutSession {
  type: 'strength' | 'cardio' | 'hiit' | 'flexibility' | 'sport';
  durationMinutes: number;
  intensityLevel: 1 | 2 | 3 | 4 | 5;
  exercises: Exercise[];
  notes: string;
}
```

## 训练强度调节规则

<AccordionGroup>
  <Accordion title="向上调节触发条件">
    满足以下任意条件时，Agent 会建议提升训练强度：
    - 连续2周完成率 ≥ 90%
    - 用户反馈"训练感觉太轻松"
    - 体测数据显示体能显著提升
  </Accordion>
  <Accordion title="向下调节触发条件">
    满足以下任意条件时，Agent 会主动建议降低强度：
    - 连续3天睡眠评分 &lt; 60
    - 用户反馈身体不适或疲劳
    - 当周完成率 &lt; 50%（可能因为强度过高）
    - 健康数据 Skill 检测到过度训练信号
  </Accordion>
  <Accordion title="保持不变的场景">
    - 用户正在适应阶段（前2周）
    - 完成率在 70-90% 之间（正常范围）
    - 用户明确表示希望维持当前节奏
  </Accordion>
</AccordionGroup>

## 与其他 Skill 的接口

| 接收方 | 数据内容 | 触发时机 |
|-------|---------|---------|
| 健康数据 Skill | 当日训练内容、强度、时长 | 每次训练完成后 |
| 饮食营养 Skill | 训练日/休息日热量需求差异 | 计划生成时 |
| 目标追踪 Skill | 计划执行进度、完成率 | 每日同步 |
