# 饮食营养 Skill

## 能力定义

饮食营养 Skill 帮助用户**理解自己的饮食结构，并在日常饮食决策中提供实时支持**。它不追求让用户遵循严苛的饮食计划，而是通过渐进式引导，帮助用户建立更健康的饮食习惯。

<Info>
  饮食营养是高度个人化的领域，Agent 的建议基于通用营养科学原则，不能替代营养师的专业评估。对于有特殊健康状况的用户，应引导其寻求专业医疗建议。
</Info>

## 核心能力矩阵

| 能力 | 描述 | 数据依赖 |
|------|------|---------|
| **饮食记录** | 支持多种方式记录膳食摄入 | 用户输入、食物数据库 |
| **营养分析** | 分析膳食的宏量/微量营养素构成 | 饮食记录、食物数据库 |
| **食谱推荐** | 根据目标和偏好推荐适合的餐食 | 用户画像、当日营养缺口 |
| **购物清单** | 根据周计划生成采购清单 | 周餐食计划 |
| **外食指南** | 在外就餐时提供更健康的选择建议 | 餐厅类型、营养目标 |

## 饮食记录的交互设计

### 多模态记录方式

饮食记录是一个高频且容易产生摩擦的行为，需要尽可能降低记录成本：

<Tabs>
  <Tab title="语音/文字描述">
    ```
    用户：刚吃了一碗牛肉面，加了个卤蛋

    Agent：记录好了！📝

           🍜 午餐估算
           牛肉面（普通份）：约 520 大卡
           卤蛋：约 80 大卡
           合计：约 600 大卡

           今日已摄入：1,050 大卡
           距离今日目标（1,800 大卡）：还剩 750 大卡

           今天蛋白质摄入目前偏低，晚餐可以考虑多补充一些肉类或豆制品。
           要我推荐几个晚餐选择吗？
    ```

    **UX 要点：** 立即给出摘要确认，不让用户等待；用直观数字呈现进度，主动衔接下一步。
  </Tab>
  <Tab title="拍照识别">
    ```
    用户：[发送餐食照片]

    Agent：我看到了你的餐食！让我来分析一下：

           🍱 识别结果
           - 米饭（约1碗）
           - 红烧肉（约4-5块）
           - 炒青菜
           - 蛋花汤

           预估热量：约 680 大卡
           蛋白质：约 28g | 碳水：约 72g | 脂肪：约 26g

           [确认] [有误差，我来修改]
    ```

    **UX 要点：** 识别结果要有修改出口，不能让用户觉得被AI"错误地记录了"。
  </Tab>
  <Tab title="快速选择">
    ```
    Agent：早餐时间到了！今天早餐吃了什么？

    [常用早餐快选]
    ☑ 燕麦粥    ☑ 鸡蛋    ☑ 牛奶
    ☑ 全麦面包  ☑ 水果    ☑ 豆浆
    [其他早餐]
    ```

    **UX 要点：** 基于用户历史记录推断常用食物，每次展示个性化的快选列表。
  </Tab>
</Tabs>

### 智能提醒设计

```
不扰人的提醒策略：
- 不在用户不活跃时发送（深夜/工作高峰期）
- 基于历史习惯推断用餐时间，在合适时机轻推
- 提醒措辞不引发压力感："该记录午餐了！" 而不是 "你还没记录午餐"
- 连续漏记3天后，主动询问记录方式是否需要调整，而不是继续催促
```

## 营养目标体系

### 基础目标计算

```typescript
interface NutritionTargets {
  // 热量目标（基于 Harris-Benedict + 活动系数 + 目标调整）
  dailyCalories: {
    baseline: number;      // TDEE
    adjusted: number;      // 根据目标调整后
    range: [number, number]; // 可接受范围
  };

  // 宏量营养素目标
  macros: {
    protein: { grams: number; percentage: number };    // 蛋白质
    carbohydrates: { grams: number; percentage: number }; // 碳水化合物
    fat: { grams: number; percentage: number };        // 脂肪
  };

  // 微量营养素关注重点（基于用户目标定制）
  micronutrientFocus: MicronutrientTarget[];
}
```

### 目标与热量调整策略

| 健康目标 | 热量调整 | 宏量营养素重点 |
|---------|---------|--------------|
| 减脂 | TDEE × 0.8（缺口20%） | 高蛋白（35%）、低碳水（35%）、适中脂肪 |
| 增肌 | TDEE × 1.1（盈余10%） | 高蛋白（30%）、高碳水（50%）、低脂肪 |
| 维持 | TDEE × 1.0 | 均衡分配（蛋白25%、碳水50%、脂肪25%） |
| 提升体能 | TDEE × 1.05-1.1 | 高碳水（55%）、中蛋白（20%）、低脂肪 |

## 食谱推荐逻辑

### 推荐策略

```
当日营养缺口分析
    ↓
过滤：用户饮食禁忌/过敏（绝对排除）
    ↓
过滤：用户不喜欢的食材/口味（降低权重）
    ↓
过滤：季节性、可获取性
    ↓
排序：营养缺口填补效率 × 用户历史喜好分 × 多样性奖励
    ↓
输出：推荐3-5个选项（保证多样性）
```

### 食谱卡片设计规范

每个食谱推荐需包含：

```
[食谱名称]
难度：⭐⭐ | 时间：20分钟 | 份量：1人份

核心营养（与今日目标的关联）
  🥩 蛋白质 28g  ← 今日目标还差 40g，这道菜填补了 70%
  🔥 热量 380大卡 ← 在今日剩余预算内

主要食材（可替换项）
  鸡胸肉 150g（可换：豆腐、虾仁）
  西兰花 100g
  橄榄油 10ml

[查看完整食谱] [添加到今日饮食计划]
```

## 外食场景支持

外出就餐是饮食管理的高难度场景，需要特别的支持策略：

<AccordionGroup>
  <Accordion title="点餐前咨询">
    ```
    用户：晚上要去火锅，怎么吃比较健康？

    Agent：火锅完全可以吃得健康！几个小技巧：

           🥬 食材选择优先级
           ✅ 多点：瘦肉片、虾、豆腐、各种蔬菜、菌菇
           ⚠️ 适量：内脏类、肥牛肉、粉条
           ❌ 少点：鱼豆腐等加工食品、饮料

           🥘 锅底选择
           番茄锅/菌菇锅 > 清汤 > 麻辣（高油高钠）

           🥣 调料
           蘸料尽量用醋+蒜泥，避免重油麻酱

           预计今晚热量：600-900大卡（取决于食材选择）
           要我根据你的今日摄入情况，建议一个食材搭配比例吗？
    ```
  </Accordion>
  <Accordion title="餐后记录">
    外食难以精确记录，应提供估算支持：
    - 提供"火锅/烧烤/自助餐"等场景的快速热量区间
    - 允许用户选择"低/中/高"消费量而非精确数字
    - 不因外食误差而过分纠正，避免引发用户焦虑
  </Accordion>
</AccordionGroup>

## 营养知识科普设计

在合适的时机，主动提供简短的营养知识，帮助用户建立正确认知：

```
用户连续三天早餐跳过 → Agent 在第四天早餐时间说：

"顺便说一个小知识：不吃早餐不一定能减少总热量摄入，
 反而容易让午餐吃得更多。

 如果早上真的不饿，一个小技巧：
 准备一杯加蛋白粉的牛奶（约200大卡，10分钟准备），
 既不会撑，又能维持上午的状态。"
```

知识科普的设计原则：
- **一次一个知识点**，不过度教育
- **与当下行为直接相关**，而非泛泛而谈
- **用行为建议收尾**，不只是说"你应该..."
