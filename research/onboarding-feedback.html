设计说明

选项卡片的设计规则
选项行结构 Emoji 图标 + 粗体主文 + 副文说明 + 右侧 check（默认隐藏）。三列信息对应不同权重：17px Bold / 12px Regular。
悬停 / 点击反馈 hover：背景从 White/6 → White/10，边框加深。tap：scale(0.98) + 背景加亮。选中：scale(1.02)，check 圈弹入，其他行 dimmed（opacity 0.28）。
Card 背景 Glass 效果：rgba(255,255,255,0.07) + backdrop-filter blur(24px)，保持渐变背景可见。
渐变标签 ✦ 12px Medium，品牌三色 clip-text。与 Figma 设计规范中 "心情选择" 标签一致。
下一步按钮状态
未选中（disabled）opacity 0.4，不可点击，防止用户跳过选择。
已选中（enabled）opacity 1，点击后触发过渡到反馈态，延迟 200ms（让确认动画先完成）。
反馈态的设计逻辑
为什么要有反馈页 选项 → 下一题 之间缺少"被接住"的感受。反馈页让 Agent 对选择做出回应，建立对话感而非表单感。
确认状态 —— 选择留存 情绪名称保留并放大（44px Bold），Emoji 同步展示，配合 ✦ 你选择了 的小标签，让用户感受到"被看见"。
Agent 回应 —— 不是提示，是理解 回应文字引用用户的选择，使用第二人称，针对每种情绪定制。有强调（bold）区分重点信息。
下一问预告 —— 减少不确定感 "接下来" 小卡片提示即将进入的问题，降低用户对流程长度的焦虑。视觉权重低于 Agent 回应。
动画节奏（时间轴）
0ms屏幕滑入（screens rail 位移）
+100ms✦ 标签淡入 + 上移
+200msEmoji 弹入（scale 0.6 → 1，spring easing）
+300ms情绪名称淡入 + 上移
+500ms分隔线展开（scaleX 0 → 1）
+600msAgent 回应整体淡入 + 上移
+850ms下一问预告卡片淡入
