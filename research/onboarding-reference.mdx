# Onboarding 设计参考

## 设计目标

运动健康 Agent 的 Onboarding 必须同时实现三件事：

```
① 收集足够的信息，让 Agent 能给出个性化响应
② 建立情感连接，让用户感到"这里真的懂我"
③ 在结束时，用户已经得到了第一个真实价值
```

这三件事要在 **8 分钟以内** 完成，且用户不应该感到"我在填表"。

---

## Onboarding 全流程图

```
[打开 App]
    │
    ▼
阶段 0：进入前（30秒）
启动屏 → 欢迎语 → "我们开始"

    │
    ▼
阶段 1：情感切入（2分钟，4步）
现在的感受 → 来这里的原因 → 过去的尝试 → 障碍是什么

    │
    ▼
阶段 2：了解你的生活（2分钟，4步）
生活节奏 → 可用时间 → 运动偏好 → 设备条件

    │
    ▼
阶段 3：数字信息（1分钟，2步）
体重/体型目标 → 时间线设定

    │
    ▼
阶段 4：首次价值时刻（2分钟）
Agent 生成个性化"启动宣言" → 第一个行动指派

    │
    ▼
阶段 5：建立习惯锚点（1分钟）
设置训练提醒 → 开启数据连接（可选）

    │
    ▼
[进入主界面]
第一条主动消息等待（2小时内发出）
```

## 阶段 0：进入前体验

### 启动屏设计

启动屏不是 Logo 展示时间，而是第一次情感定调的机会。

**文案方向（三选一，基于 A/B 测试选择）：**

```
版本 A（共鸣型）：
"你知道健康很重要。
 但你不需要另一个 App 告诉你该做什么。
 你需要的是一个真正了解你的伙伴。"

版本 B（行动型）：
"不是计划，是改变。
 从今天开始。"

版本 C（关系型）：
"你好，我一直在等你。
 准备好了解一下彼此吗？"
```

**视觉设计原则：**
- 不用健身模特、完美身材图片（会引发用户的自我比较焦虑）
- 使用温暖、真实感的插图或抽象视觉
- 主色调传递"可信赖的朋友"感，而非"专业健身机构"感

## 阶段 1：情感切入

### 设计原则

这是整个 Onboarding 最重要的部分。**用户在这4步对话里，决定了"这个 App 是否懂我"**。

每一个问题的选项，都要让用户感到"这里有我的答案，它理解我的处境"。

### 第1步：此刻的状态

```
Agent 说：
"你好！我很高兴你在这里。
 
 先不问目标和计划，我想先知道你现在感觉怎么样？"

选项设计（要有共鸣感，不能是情绪标签）：
○ 有点迷茫，不知道从哪里开始
○ 下定决心要改变，但需要帮助
○ 试了很多方法都没坚持，想再试一次
○ 状态还不错，想更进一步

[设计意图]
这个问题没有"正确答案"，所有选项都会被接纳。
目的是让用户感到被看见，同时让 Agent 获得情绪基调参考。
```

**响应示例（选择"试了很多方法都没坚持"）：**
```
Agent：
"我听到了。'又开始了'的感觉其实很不容易，
 需要很大的勇气。

 很多来到这里的人都有过类似的经历。
 这次我们换一种方式——
 先搞清楚为什么之前会停下来，才能这次走得更远。"
```

### 第2步：来这里的原因

```
Agent：
"你今天打开这个 App，最直接的原因是什么？
 （选一个最接近的就好）"

选项：
○ 体重/体型让我不太舒服
○ 感觉身体越来越差，想变得更健康
○ 想建立运动习惯，但一直没做到
○ 想让自己状态更好（精力、睡眠）
○ 有一个具体的目标（比赛、婚礼、其他）

[设计意图]
这个问题区分了用户的核心驱动力是"逃离负面"（减重、健康变差）
还是"追求正面"（状态更好、有具体目标）。
这会影响整个 Agent 的激励策略。
```

### 第3步：过去的尝试

```
Agent：
"你有没有认真尝试过健身或健康管理？"

选项 A（有过）：
"有，尝试过 ____"
（开放式补充，或从常见选项选择：健身App/私教/自己计划/减肥饮食...）

选项 B（没有）：
"基本上没有，这是真正的第一次"

[如果选择了"有过"]

Agent继续：
"是什么让你停下来了？
 （这不是在追责，我真的想理解）"

○ 计划太难，跟上不了
○ 太忙，生活一乱就停了
○ 看不到效果，失去了动力
○ 其实不知道，就这样停了
○ 受伤了或者身体原因

[设计意图]
让用户"命名"自己的失败原因，有两个作用：
1. 帮助 Agent 避开这个用户的失败模式
2. 让用户感到"被理解"而非"被评判"
```

**响应示例（选择"太忙，生活一乱就停了"）：**
```
Agent：
"这是最常见的原因之一，也是很真实的挑战。

 生活越来越不可预期——我们设计的计划
 要能在你最忙的时候也能坚持，而不只是
 在状态最好的时候才有效。

 我会把这一点记住。"
```

### 第4步：生活节奏（过渡到实际信息）

```
Agent：
"再问一个问题，然后我们就来制定你的方案。

 你平时的生活是什么节奏？"

○ 朝九晚五，相对规律
○ 工作时间不固定，经常加班
○ 经常出差/在外跑
○ 在家工作/灵活时间较多
○ 需要照顾家人，时间碎片化

[设计意图]
这是从"情感收集"过渡到"实际信息收集"的过渡问题。
它仍然是在理解用户的处境，而非收集表单数据。
```

## 阶段 2：了解你的生活

这个阶段开始收集实际需要的计划信息，但继续保持对话的温度。

### 第5步：时间窗口

```
Agent：
"好，我大概了解你的生活节奏了。

 每次运动，你最多能留出多少时间？"

○ 20-30分钟（很短，但没关系）
○ 30-45分钟
○ 45-60分钟
○ 1小时以上（时间不是问题）

[无论选择哪个选项，Agent 都给出积极回应]

选择"20-30分钟"时：
"20分钟完全可以做很多事情！很多有效的训练
 其实在20分钟内就能完成。
 我们就按这个来设计。"
```

### 第6步：每周频率

```
Agent：
"每周你觉得哪几天可以运动？"

[以日历形式展示一周7天，用户点选]

[Agent 实时计算]
选了3天 → "每周3次，很好的起点"
选了5天 → "5次！雄心勃勃。我会确保计划里有足够的恢复日"
选了1-2天 → "2次也完全够。质量比数量更重要"
```

### 第7步：运动偏好

```
Agent：
"你喜欢什么类型的运动？或者你最不排斥哪种？"

[多选，可以选0个]

☑ 跑步/走路        ☑ 力量训练（器械/哑铃）
☑ 瑜伽/拉伸        ☑ 游泳
☑ 骑行              ☑ 团课/跳操
☑ 球类运动          ☑ 其他

[如果一个都不选]
"没有特别喜欢的？完全没问题。
 我会帮你找到你'不讨厌'的运动——
 这已经是很好的开始了。"
```

### 第8步：设备和场地

```
Agent：
"你通常在哪里运动？有什么设备可以用？"

○ 家里，没有器械（只有地板和身体）
○ 家里，有一些器械（哑铃/瑜伽垫等）
○ 小区/公园（户外为主）
○ 健身房（全套设备）
○ 不固定，各种情况都有
```

## 阶段 3：数字信息

到这一步，用户已经对 Agent 建立了初步信任。现在可以收集敏感数字数据。

### 第9步：健康目标量化

```
Agent：
"你的主要健康目标是什么？
 说说最直接的期望。"

○ 减重/减脂（希望体重/体型有变化）
  → 追问：大概想减多少？不确定的话可以先选"看效果再说"
○ 增肌/塑形（想要更紧实的身材）
○ 提升体能（跑得更远、更有力气）
○ 整体健康（睡眠、精力、心情状态）
○ 建立运动习惯（目标本身就是坚持下去）

[如果选择了减重]
Agent：
"你现在大概多少斤？想到多少斤？
 不想透露数字也完全没问题，告诉我'希望减少的量'也行。"
```

**设计关键：** 体重是可选填写的，不是强制的。如果用户不填，Agent 用体能感受作为进度基准。

### 第10步：时间线设定

```
Agent：
"你有没有一个希望看到变化的时间？"

○ 越快越好，我想要快点看到结果
○ 3个月，给自己一个短期目标
○ 半年左右，慢慢来
○ 没有时间压力，养成习惯就好

[无论选哪个，Agent 给出诚实但积极的回应]

选择"越快越好"：
"理解！我只需要提醒你一件事：
 可持续的进步比快速但短命的改变更有价值。
 
 我会给你一个'积极但不激进'的节奏——
 快到能看见变化，慢到能真的坚持。"
```

## 阶段 4：首次价值时刻

这是整个 Onboarding 的高潮——Agent 将所有信息整合，生成一份"个性化启动宣言"。

### 启动宣言设计

**不是表单汇总，而是真正理解的呈现：**

```
❌ 表单汇总风格（避免）：
"你的信息：
 目标：减重
 每周频率：3次
 时间：30分钟
 设备：家里，哑铃"

✅ 启动宣言风格（推荐）：
Agent：

"好了，我现在对你有了一些了解。

 你之前试过，停下来是因为计划太难跟上——
 所以这次我们从更小、更稳的步子开始。

 你每周有3个晚上可以用，每次30分钟，
 在家用哑铃练。

 接下来3个月，我们不追求完美，
 只追求'每周三次，持续下去'。

 这一件事如果做到了，
 其他所有改变都会跟着来。

 准备好了吗？"

[是的，开始吧]  [我有一个问题]
```

### 第一个行动指派

Onboarding 完成后，立即给用户一个今日（或明日）的具体行动：

```
Agent：
"今天我不给你一个'计划'，我给你一个行动——
 今晚，在你通常睡觉前1小时，做这件事：

 🎯 10分钟热身 + 3组哑铃深蹲

 这不是真正的训练，这是'我们已经开始了'的信号。

 完成后来告诉我感觉怎么样。

 几点方便？我设一个提醒。"
```

**设计意图：**
- 第一个行动要小，确保成功体验
- 第一个行动要今天或明天，不能"下周开始"
- 要求用户汇报，为第一次对话创造理由

## 阶段 5：习惯锚点

### 提醒设置

```
Agent：
"最后一步——设置一个提醒，这会把运动变成日历上的真实事件。

 你想把训练提醒放在什么时间？
 [时间选择器：上午 / 中午 / 傍晚 / 晚上]

 具体几点？[滚轮选择]"
```

**提醒文案设计（非通用模板）：**
```
❌ "你好，该运动了！"
✅ "你的30分钟到了，来吗？" （结合用户设定的时长）
✅ "[用户名]，今天是你的第3天训练。" （加入计数感）
```

### 数据连接（可选，不强制）

```
Agent：
"可选项：如果你有运动手表或健身追踪器，
 连接后我能给你更精准的建议。
 现在不连接也完全没关系，以后随时可以。

 [连接 Apple Health]  [连接 Google Fit]
 [暂时跳过，直接开始]"
```

**设计原则：** 数据连接放在 Onboarding 的最末端，且明确标注是可选的，降低隐私焦虑导致的退出率。

## Onboarding 完成后：第一条主动消息

Onboarding 完成 2-4 小时后（不是立即），Agent 发送第一条主动消息。

### 消息设计规范

**基于 Onboarding 信息的个性化示例：**

```
[场景：用户选择了"之前因为太忙而停下来"，目标是减重，晚上7点训练]

Agent 在晚上 6:45 发送：

"快到你的运动时间了。

 今天是第一天，不需要完美，只需要开始。
 
 记得你说过之前因为太忙经常停下来——
 今天就算只做了10分钟也算数，
 重要的是今晚你真的动了。
 
 我在这里，完成后告诉我怎么样。"
```

**第一条消息的必要元素：**
1. 提及用户在 Onboarding 中说过的具体内容（证明 Agent 在听）
2. 降低门槛（"做了10分钟也算"）
3. 给予期待感（"完成后告诉我"）

## 首周体验设计（Day 1-7）

### 每天的互动节奏

| 时间 | 互动内容 | 主动/被动 | 设计目的 |
|-----|---------|---------|---------|
| Day 1 早晨 | 今日训练提醒 + 行动指引 | 主动 | 建立期待感 |
| Day 1 训练后 | 完成确认 + 即时庆祝 | 被动响应 | 强化正向体验 |
| Day 2 | 询问昨天训练感受 + 今日安排 | 主动 | 建立每日对话节奏 |
| Day 3 | 如果是休息日：主动科普/小知识 | 主动 | 维持连接感 |
| Day 4 | 第二次训练 + 体能感受询问 | 被动响应 | 获取适应性数据 |
| Day 5 | 本周进度小结（早发送） | 主动 | 建立周期感，给进步感 |
| Day 6-7 | 周末安排建议（更灵活） | 主动 | 适应生活节奏 |

### 关键时刻脚本

**Day 3：首次不想运动（高风险时刻）**

当用户在训练提醒后 2 小时没有反应：

```
Agent：
"今天的训练时间过了，你还好吗？

 不是要催你——我只是想知道发生了什么。
 是太忙了、太累了，还是只是今天不想动？
 
 都可以，没关系。告诉我。"

[响应：太忙/太累]
Agent：
"完全理解。今天跳过，明天补回来——
 或者今晚找5分钟做个简单的拉伸也算。
 
 连续的感觉比完美的计划重要。
 我们明天继续。"

[响应：不想动/情绪不好]
Agent：
"今天不想动，这是很正常的感觉。
 
 我有一个建议：今晚不用做训练，
 就出门走10分钟，呼吸一下外面的空气。
 
 走路可以很神奇地改变情绪——
 不是作为运动，就是一次散步。
 要不要试试？"
```

**Day 7：第一周完成庆祝**

```
Agent：
"第一周完成了。

 我知道这听起来好像只是一周，
 但我知道这一周里有多少次你可以选择不做，
 而你还是做了。

 你完成了 [N] 次训练，消耗了约 [X] 大卡，
 但更重要的是——你证明了自己可以开始。

 下周我们继续，步子会大一点点。"
```

## Onboarding 流失预防

### 流失高风险点与应对

| 流失点 | 触发条件 | 干预策略 |
|-------|---------|---------|
| Onboarding 中途放弃 | 在某一步停留 >2分钟未操作 | 轻提示"可以先跳过这个，回头再填" |
| 完成 Onboarding 但未完成首个行动 | 第一天晚 8 点未触发首个行动 | 第二天早晨发送低门槛替代方案 |
| 第一周内连续2天未互动 | 48小时无任何打开记录 | 发送情感型（非任务型）消息 |
| 第一次说"我不想运动" | 用户拒绝了训练建议 | 不重新推销训练，先理解原因 |

### 重新激活消息设计

用户已流失（5天+未打开）后的召回消息设计原则：

```
❌ 功能型召回（无效）：
"你有3天没有完成训练了，快回来！"

✅ 关系型召回（有效）：
"已经有5天没收到你的消息了，你还好吗？
 
 不管是生活太忙、还是只是需要暂停一下，
 这都是可以的。
 
 如果你准备好了，我在这里。"
```

召回消息只发送一次，不要反复打扰已流失用户。

## Onboarding 效果评估指标

### 核心漏斗指标

```
打开 App
    │ 转化率目标 ≥ 85%
    ▼
开始 Onboarding
    │ 转化率目标 ≥ 75%
    ▼
完成 Onboarding（全部10步）
    │ 转化率目标 ≥ 60%
    ▼
完成首个行动（第一次训练/打卡）
    │ 转化率目标 ≥ 50%
    ▼
Day 7 仍然活跃
```

### 质量指标

- **情感连接质量：** Onboarding 结束后调查"Agent 理解你吗？" NPS 目标 ≥ 8/10
- **首次价值感知：** "完成 Onboarding 后，你对接下来的计划有信心吗？" 目标 ≥ 70% 回答"有"
- **首个行动完成率：** Onboarding 当日/次日完成首个指派行动的比例 ≥ 55%
