# 竞品分析

## 分析框架

本文从以下六个维度对竞品进行拆解，聚焦与运动健康 Agent 设计最相关的决策：

| 维度 | 分析重点 |
|-----|---------|
| **Onboarding 流程** | 信息收集策略、首次到达价值的路径 |
| **个性化深度** | 如何理解用户、适配程度 |
| **主动性设计** | 产品是否主动介入，介入方式 |
| **激励机制** | 如何维持用户长期参与 |
| **情感设计** | 产品是否建立情感连接 |
| **对我们的启示** | 值得借鉴的点、应该避免的坑 |

---

## Noom — 行为改变心理学的最佳实践者

### 产品定位

以行为改变心理学（CBT）为核心的"减重教练"，主打可持续的健康习惯改变，而非快速减重。

### Onboarding 拆解

**流程长度：** 约 20-25 步，但用户感知流畅（设计成"测验"而非"表单"）

**信息收集策略：**
```
第一组问题（情感切入）：
  ① 你的主要目标是什么？（减重 / 保持健康 / 改变习惯）
  ② 你在饮食上最大的挑战是什么？（选项设计充满同理心）
     - "我在压力大的时候容易暴食"
     - "我知道该怎么吃，但就是控制不住"
     - "我没时间准备健康的食物"

第二组问题（行为历史）：
  ③ 你以前尝试过什么减重方法？
  ④ 效果怎么样？为什么最终没有坚持？

第三组问题（生活背景）：
  ⑤ 你的生活节奏怎样？（工作繁忙 / 久坐 / 体力劳动）
  ⑥ 你通常一天吃几餐？

第四组问题（量化数据）：— 放在最后收集
  ⑦ 你的当前体重和目标体重
  ⑧ 时间线设定
```

**关键设计洞察：**
- 把"你为什么以前失败了"变成选择题，降低负面情绪
- 体重这类敏感数据放在最后，等用户已经建立信任再收集
- 每3-4步插入一段"你并不孤单，73%的人有同样感受"的数据卡，持续给予情感支撑

**时间到首次价值：** 约8-10分钟，Onboarding 结束时即给出"你的专属减重计划预览"

### 激励机制

- **颜色区域食物系统：** 绿/黄/红三色分类食物，极简但有心理锚点
- **每日称重习惯养成：** 每天第一件事记录体重，配合数据折线图"看见"微小进步
- **每日课程（1-5分钟）：** 不只是追踪，而是教用户"为什么"，建立知识感

### 对我们的启示

| 值得借鉴 | 需要超越 |
|---------|---------|
| 情感先行的问题排序（痛点→历史→数据） | 每日课程形式偏"工具"，缺少对话感 |
| 让用户选择"我的失败原因"而非填写 | 分组功能较弱，缺少真实社交陪伴感 |
| 前几天刻意降低难度，保证成功体验 | 7天后逐渐变成"数据记录工具"，陪伴感下降 |
| 体重以"趋势"展示，不强调日波动 | 教练功能付费壁垒较高，免费版体验断层 |

## Nike Training Club (NTC) — 优雅个性化的标杆

### 产品定位

以训练内容为核心，结合个性化推荐和品牌文化的综合健身 App。

### Onboarding 拆解

**流程长度：** 约 5-7 步，极简

```
① 运动水平自评（初级/中级/高级）
② 主要目标（减脂/增肌/提升体能/保持健康）
③ 每周可用天数
④ 可用设备（无器械/哑铃/完整健身房）

→ 立即进入首个训练推荐
```

**时间到首次价值：** 约 2 分钟，是竞品中最短的

**关键设计洞察：**

> "不把 Onboarding 当成信息收集，而是当成个性化引擎的启动仪式"

NTC 的 Onboarding 视觉设计极度精良——每一步都是全屏大图 + 单一问题，让用户感觉像在做一个品牌体验测试，而不是填写注册表单。

**个性化推荐质量：**
- 基于 4 个维度即能生成合理的训练推荐
- 首次训练推荐的难度经过精心校准，设计为"略低于用户水平"，确保成功体验

### 内容质量

NTC 的训练视频由 Nike 专业教练录制，品质极高。这创造了一个重要的体验层：**即使个性化做得一般，内容质量本身也在创造价值**。

### 主动性设计

NTC 的主动性较弱——它更像一个"我来时用"的工具，而非"主动陪伴我"的伙伴。推送较少，以内容更新为主。

### 对我们的启示

| 值得借鉴 | 需要超越 |
|---------|---------|
| 极简 Onboarding，4个维度即可启动 | 缺乏持续性的个人关系感，更像"内容平台" |
| Onboarding 每步的视觉体验极高 | 没有记忆能力，每次打开都是"陌生人" |
| 首次推荐内容难度精心校准 | 缺乏主动介入，完全被动等待用户 |
| 用品牌文化增加情感认同感 | 训练以外的健康维度（营养、睡眠）覆盖薄弱 |

## MyFitnessPal — 数据能力最强但 UX 体验最差

### 产品定位

以饮食追踪为核心的综合健康记录工具，全球最大的食物数据库。

### Onboarding 拆解

**流程长度：** 约 15 步，传统表单形式

```
收集项目（几乎全部在 Onboarding 完成）：
- 姓名、邮箱、密码
- 生日、性别
- 身高、体重、目标体重
- 每周减重速度
- 活动水平
- 目标（减重/维持/增重）
```

**核心问题：**
```
❌ 第一步就要求邮箱注册
❌ 所有信息收集一气呵成，缺乏情感过渡
❌ 没有"首次价值时刻"——完成表单后进入的是空白界面
❌ 完全没有情感层，像在填政府表格
```

**时间到首次价值：** 约 5-8 分钟，但首次价值体验较差（进入空界面，不知道该做什么）

### 数据能力 vs UX 体验的矛盾

MyFitnessPal 最大的悖论：它拥有最强大的食物数据库（600 万+ 食物条目），但食物搜索体验极差：

```
用户搜索流程（实际体验）：
用户输入"红烧肉"
→ 搜索结果出现 50+ 条（来源杂乱，卡路里差距极大）
→ 用户不知道该选哪个
→ 用户随机选一个，或直接放弃记录

这个摩擦点是最大的流失来源之一
```

### 对我们的启示

| 值得借鉴 | 需要避免 |
|---------|---------|
| 食物数据库覆盖广度的思路 | 把 Onboarding 当成数据采集任务 |
| 宏量营养素追踪的精细度 | 用户进入后面对空白界面，没有引导 |
| 与第三方设备的数据同步广度 | 用户每次打开都感觉"很重" |
| 社区功能的内容生态 | 没有情感层，纯工具属性导致黏性低 |

## Whoop — 以数据驱动的恢复导向型设计

### 产品定位

面向运动表现优化人群的生理数据监测平台，以 HRV 和"恢复准备度（Recovery Score）"为核心。

### Onboarding 拆解

Whoop 的 Onboarding 几乎不收集问题——因为设备会自动建立你的基线数据。

```
Whoop Onboarding（极简）：
① 配对硬件设备（蓝牙）
② 简单的个人基本信息
③ 设定运动目标强度偏好

→ 开始7天"基准期"：Whoop 先观察你，再给建议
```

**"基准期"设计的天才之处：**

```
前7天，Whoop 不给任何建议。它只是在观察和收集你的基线数据。
第8天，基于你个人的基线，给出第一个Recovery Score。

这个设计解决了一个核心问题：
健康数据的意义不在于绝对值，而在于相对于你自己的基线。
HRV 60ms 对某人是很好，对另一人可能偏低。
```

### 核心 UX 概念：每日三问

每天早晨，Whoop 只问三件事：

```
Recovery（恢复准备度）: 今天适合高强度训练吗？[0-100]
Strain（负荷目标）: 今天建议的运动负荷是多少？[0-21]
Sleep（睡眠表现）: 昨晚的睡眠质量如何？[0-100]
```

这三个数字让复杂的生理数据变得可操作：用户不需要理解 HRV，只需要理解"今天恢复得好不好"。

### 对我们的启示

| 值得借鉴 | 需要超越 |
|---------|---------|
| "基准期"设计——先观察，再建议 | 纯数据视角，缺乏情感温度 |
| 将复杂数据压缩成三个可操作数字 | 高度依赖硬件，无设备用户体验割裂 |
| 相对个人基线而非绝对值评估 | 对话能力几乎为零，无法解释"为什么" |
| 推送时机设计（早晨日报，一天一次） | 价格极高，大众用户门槛高 |

## Future — AI 教练的高端参考

### 产品定位

AI 加真人教练混合模式，每位用户匹配一名专属教练，通过 App 进行全程指导。

### Onboarding 拆解

```
Future 的 Onboarding 是一次"匹配对话"：

① 填写基本健康信息（表单）
② 选择训练偏好和目标
③ 系统推荐匹配的教练（展示教练照片、背景、风格）
④ 用户选择教练
⑤ 教练主动发出欢迎语音/视频 → 建立真实人际连接
```

**关键洞察：首条消息的温度决定留存**

Future 的教练会在用户完成匹配后 24 小时内发送一条个性化欢迎消息，提及用户填写的具体目标：

```
教练："嗨 Sarah！我看到你想在3个月内完成第一个5公里跑，
      太棒了！我自己是在28岁才开始跑步的，我们有共同点。
      
      我已经为你安排了第一周的计划，从周一开始。
      但在开始之前，我想问你一个问题：
      你以前跑步主要是什么阻碍了你？"
```

这条消息让用户感受到"真实的人在等待我"。

### 对我们的启示

| 值得借鉴 | 需要超越 |
|---------|---------|
| 首次消息的个性化温度（提及具体目标） | 真人教练成本极高（$149/月），难以规模化 |
| "教练匹配"增加关系感 | Agent 需要达到同等的"被记住感" |
| 第一周高频互动建立信任 | 真人教练的响应有延迟（非实时） |
| 教练主动发起，不等用户 | Agent 可以做到 24/7 实时响应 |

## Headspace — 非健身类 Onboarding 最佳参考

### 为什么分析冥想 App

Headspace 是数字健康领域 Onboarding 设计公认最好的产品之一，其方法论完全可迁移到运动健康场景。

### Onboarding 核心策略

**策略一：用"感受"而非"功能"引导**

```
❌ 功能导向："Headspace 提供 500+ 冥想课程，覆盖睡眠、专注、减压..."
✅ 感受导向："你现在感觉怎么样？今天你来这里，是因为什么？"
             - 压力太大
             - 睡不好
             - 思绪纷乱，需要安静一下
             - 我只是想尝试看看
```

**策略二：Onboarding 本身就是产品体验**

Headspace 的 Onboarding 包含一段 3 分钟的引导冥想：
- 这不是"学习如何使用产品"，而是"直接体验产品"
- 用户在 Onboarding 结束前就已经得到了真实价值

这个设计原则对运动健康 Agent 极有参考价值：
> **Onboarding 结束时，用户应该已经有了第一次有价值的体验，而不只是"完成了注册"**

**策略三：进度感设计**

```
"你已经完成了 Day 1"
[1] [2] [3] ... [10]

即使只完成了第一天，也能在视觉上感受到"我已经开始了"
和"后面还有很多值得期待的内容"
```

### 对我们的启示

| 值得借鉴 | 说明 |
|---------|------|
| Onboarding 包含直接产品体验 | 第一次对话结束时用户就已完成了第一个行动 |
| 用"现在感受"切入，而非"未来目标" | 更贴近用户当下的心理状态 |
| 视觉化的"已开始"进度感 | 降低放弃的心理门槛 |
| 问题设计不判断，只接纳 | 所有选项都是被允许的，没有"错误答案" |

## 竞品 Onboarding 横向对比

### 关键指标比较

| 产品 | Onboarding 步数 | 首次价值时间 | 情感温度 | 个性化深度 | 主动介入 |
|-----|----------------|------------|---------|-----------|---------|
| Noom | 20-25 步 | ~10分钟 | ★★★★★ | ★★★★☆ | ★★★★☆ |
| NTC | 5-7 步 | ~2分钟 | ★★★☆☆ | ★★★☆☆ | ★★☆☆☆ |
| MyFitnessPal | ~15 步 | ~8分钟 | ★☆☆☆☆ | ★★☆☆☆ | ★☆☆☆☆ |
| Whoop | ~5 步 | 7天后 | ★★☆☆☆ | ★★★★★ | ★★★☆☆ |
| Future | ~10 步 | <24小时 | ★★★★★ | ★★★★☆ | ★★★★★ |
| Headspace | ~8 步 | ~5分钟 | ★★★★★ | ★★★☆☆ | ★★★☆☆ |

### 竞品的共同盲点

通过分析，所有竞品都存在以下不足，这是我们的差异化机会：

1. **没有持续记忆**：每次打开都像"陌生人"，无法基于历史对话建立关系
2. **主动性有限**：要么没有主动介入，要么只是发推送通知，缺乏真实的"主动对话"
3. **技能边界割裂**：运动、饮食、睡眠、心理各自为政，没有整合的健康视角
4. **情感层薄弱**：能追踪数据，但不能"理解感受"

## 设计启示总结

基于以上分析，对运动健康 Agent Onboarding 的核心设计建议：

<Steps>
  <Step title="从感受切入（Noom + Headspace）">
    第一个问题不问体重，不问目标，而是问"你现在感觉怎么样"或"你来这里，是因为什么"。
  </Step>
  <Step title="让 Onboarding 本身就有价值（Headspace）">
    Onboarding 结束时，用户已经完成了第一个有意义的行动，而不只是"填完了表单"。
  </Step>
  <Step title="敏感数据放最后（Noom）">
    体重、年龄等数字数据在情感连接建立之后再收集，不要第一步就要求。
  </Step>
  <Step title="首条消息要个性化且有温度（Future）">
    Onboarding 完成后，Agent 的第一条主动消息必须提及用户说过的具体内容，不能是通用模板。
  </Step>
  <Step title="基准期先观察再建议（Whoop）">
    给用户设置一个"基准期"概念，让 Agent 先观察用户的习惯和模式，再给出真正个性化的建议。
  </Step>
  <Step title="进度感让开始变得有仪式感（Headspace + NTC）">
    让用户在完成 Onboarding 后感受到"我已经开始了"，而不是"我终于完成了注册"。
  </Step>
</Steps>
