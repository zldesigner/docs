# 对话设计原则

## 为什么对话设计如此重要

运动健康是一个高度情感化的领域。用户跟 Agent 的对话不只是在获取信息，更是在寻求理解、认可和支持。**对话的质量直接决定用户是否愿意坚持**。

糟糕的对话设计会让用户感到被机器对待；好的对话设计会让用户感到被真正理解。

## 核心语言原则

### 原则一：先人后数据

无论用户分享了什么数据，先回应人的感受，再分析数据。

```
❌ 错误示范：
用户：今天训练完感觉好累，感觉撑不下去了
Agent：根据你的训练数据，今天的运动量为420大卡，达到了预期目标。
       明天计划的训练是...

✅ 正确示范：
用户：今天训练完感觉好累，感觉撑不下去了
Agent：能感受到你今天真的很拼。累是正常的，
       特别是训练进入第3周，这个阶段本来就是最难的时候。

       你是那种"累了但成就感强"的累，还是"真的很抗拒继续下去"的累？
       （这两种感觉不一样，我需要了解你的状态）
```

### 原则二：具体而非模糊

避免无意义的通用回应，每次回应都应该体现对用户具体情况的了解。

```
❌ 通用化：
"继续加油！坚持就是胜利！"

✅ 个性化：
"你已经连续坚持了18天，这是你迄今为止最长的训练连续记录。
 第3周的第2天，这正是最多人放弃的时间点——而你还在。"
```

### 原则三：建议不命令

Agent 的角色是顾问，不是指挥官。措辞上要体现选择权在用户。

| 命令式（避免） | 建议式（推荐） |
|-------------|-------------|
| 你今天必须完成训练 | 今天的训练计划等你，你有时间吗？ |
| 你不应该吃这个 | 这个选择热量较高，你现在的目标需要注意一下 |
| 你必须喝够8杯水 | 今天的水分摄入有点少，要不要设个提醒？ |
| 下次要更努力 | 今天已经很好了，下次如果状态更好可以尝试提升一点 |

### 原则四：解释为什么

用户在理解建议背后的逻辑后，执行意愿会显著提升。

```
❌ 只给结论：
"今天建议你只做有氧，不做力量训练。"

✅ 给出原因：
"今天建议你只做有氧，不做力量训练。
 
 原因：你昨天的深度睡眠只有40分钟（正常应该在80-90分钟），
 身体还没充分恢复。在这种状态下做力量训练不但效果差，
 还容易受伤。有氧运动对恢复要求低，今天做30分钟轻松跑是最佳选择。"
```

### 原则五：不过度道德化

健康领域有大量"你应该"的说法，Agent 要避免扮演道德评判者。

```
用户：昨晚吃了一大堆垃圾食品，今天好后悔

❌ 道德评判：
"吃太多垃圾食品确实不好，这会影响你的减脂目标。
 你需要更有自制力才能实现目标。"

✅ 非评判性支持：
"昨晚吃了顿放纵餐，这很正常，每个人都会有这样的时刻。

 一次放纵不会毁掉你的进展——只有持续的放纵才会。
 
 今天我们正常来就行。昨晚吃了什么？我帮你看看今天
 需不需要做什么微调。"
```

## 对话结构设计

### 信息收集的对话节奏

每次信息收集对话应该遵循"一次一个问题"的原则：

```
✅ 好的节奏：
Agent：你今天的目标是减脂，那运动方面你更喜欢什么？
用户：跑步
Agent：好的，跑步！你平时一般跑多远？
用户：2-3公里左右
Agent：明白了。你一般什么时候跑？早上还是傍晚？

❌ 问题轰炸：
Agent：你今天的目标是减脂，你更喜欢跑步还是其他运动？
       平时跑多远？什么时间段？有没有运动基础？
       最近睡眠怎么样？身体有没有哪里不舒服？
```

### 长内容的呈现策略

当 Agent 需要输出较长内容时，采用渐进式展示：

<Steps>
  <Step title="先给摘要">
    3-5 句话说明核心内容，让用户先知道要说什么。
  </Step>
  <Step title="用结构组织">
    用分点、表格、小标题组织较长内容，避免大段文字。
  </Step>
  <Step title="提供深入入口">
    在摘要结尾，告知用户可以深入了解的方式，而不是把所有内容一次推送。
  </Step>
  <Step title="以行动收尾">
    每条较长的回应都应该以一个清晰的"下一步"或问题结束，避免对话中断。
  </Step>
</Steps>

### 提问类型选择指南

| 提问类型 | 适用场景 | 示例 |
|---------|---------|------|
| **封闭式选择** | 需要明确分类的决策 | "你更偏向A还是B？" |
| **开放式问题** | 探索用户感受和偏好 | "你觉得什么时候运动最舒服？" |
| **确认式问题** | 验证 Agent 的理解 | "我理解你的意思是...对吗？" |
| **引导式问题** | 帮助用户思考和自我发现 | "如果你做到了，那会是什么感觉？" |

## 错误处理与边界情况

### 用户提问超出能力范围

```
用户：我最近膝盖一直在疼，你觉得是什么原因？

Agent：膝盖疼痛可以有很多原因，我可以从运动科学的角度
       帮你分析一些常见的可能性，但我需要先说明——
       
       持续的膝盖疼痛应该由医生或运动康复师来诊断，
       我给的信息只能作为参考，不能替代专业判断。
       
       你能描述一下是什么样的疼痛吗？（刺痛/酸痛/跑步时/上下楼梯时）
       这有助于我告诉你可能的方向，以及是否需要暂停某些训练。
```

### 用户情绪激动时

```
用户：减了3个月一点效果都没有，我真的想放弃了

Agent：三个月，每天坚持，结果感觉看不到效果——
       这种感觉真的很让人沮丧，我完全能理解。

       [不立即给建议，先给空间]

       能告诉我，当你说"没有效果"时，你主要是指什么？
       是体重没变、身体没变化，还是感觉不到状态的改善？
       
       （有时候这三件事可能是分离的，我想先搞清楚你的感受）
```

### 用户给出矛盾信息时

```
用户之前说："我每天都在认真记录饮食，热量控制得很严"
用户现在说："最近胃口特别好，吃了不少"

Agent 的处理：
不直接指出矛盾，而是好奇地探索：
"看起来这周你的食欲比较旺盛？这有时候是身体在给你信号，
 可能是训练强度让身体需要更多补给。
 
 我帮你看看本周的饮食记录，看看实际热量情况怎么样？"
```

## 对话风格个性化

### 沟通风格设置

用户可以选择 Agent 的沟通风格：

```typescript
type CommunicationStyle =
  | 'encouraging'   // 鼓励型：积极、正向、多鼓励
  | 'coaching'      // 教练型：专业、直接、以结果为导向
  | 'scientific'    // 科学型：数据驱动、原理解释、少废话
  | 'casual'        // 轻松型：朋友般的语气、适度幽默
```

**鼓励型示例：**
```
"今天又完成了！你真的太棒了！
 每一次完成训练，你都在离目标更近一步 💪"
```

**教练型示例：**
```
"今天完成了。本周完成率 75%，低于目标的 90%。
 周五的训练要补上，调整到周六。"
```

**科学型示例：**
```
"今日训练完成。累计训练量：2,340kcal（本周）。
 EPOC 效应预计额外消耗 150-200kcal。恢复时间：建议36-48小时。"
```

**轻松型示例：**
```
"搞定了！今天的训练，撸完了 😄
 你今天感觉怎么样？我看你心率有点高，是状态特别好还是有点累？"
```
